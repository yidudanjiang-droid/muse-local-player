# Muse 本地音乐使用教程

## 1. 安装与首次使用

在 GitHub Release 中，近年 Android 手机和平板通常选择 `arm64-v8a`；不确定设备 ABI 时选择 `universal`。安装后，Muse 会把 APK 内专题音频作为首页主内容，同时可以按系统提示授予读取设备音乐和发送播放通知所需的权限。权限状态可在应用内查看；拒绝设备媒体权限不会影响 APK 内置专题的离线播放。

进入首页后，优先选择“本期专题”或专题目录中的某一期。专题全览会显示本期介绍、曲目、章节、节目笔记、真实时长识别状态和完成进度。点按“从头开始”会从第一首播放完整专题；点按“继续收听”会从本期保存的断点继续。

## 2. 专题收听

在专题全览中，点按曲目会建立该期完整专题队列后开始播放。章节、歌词、节目笔记和书签都可以作为精确入口；进入后应用会先切换到正确专题，再定位到目标时间。播放页的上一首、播放/暂停、下一首紧贴真实进度条，专题曲目播放时还会显示当前专题和完成进度，并可返回节目单。

“跨专题继续”会集中展示其他专题中尚未结束的断点。点按任意恢复卡片即可切换专题并恢复原来的曲目和位置。播放队列不会把其他专题或设备音乐混入当前专题。

## 3. 全局搜索

顶部搜索支持离线查找全部专题的曲目标题、艺人、专辑、专题名称、章节标题、节目笔记和发布者提供的 LRC 歌词。搜索结果会标示所属专题和内容类型。点按曲目会从该曲目开始播放完整专题，点按章节、歌词或书签会定位到对应时间。

搜索不联网，也不会自动下载或生成歌词。LRC 需要由发布者放在与音频同目录、同文件名的位置，例如 `03-track.mp3` 对应 `03-track.lrc`。

## 4. 收藏、历史与书签

播放页可以收藏当前曲目；首页和资料库可查看收藏和播放历史。书签保存真实时间轴位置，适合记录专题中的重点段落。书签和断点只写入应用私有 DataStore，不会上传。若设备媒体文件被删除，失效的设备书签会自动清理；APK 内专题文件由当前安装包管理。

## 5. 播放设置

播放页支持顺序、随机、单曲循环和不循环等播放策略，可调整播放速度，并按需启用混音与淡入淡出。睡眠定时可以按剩余时间或播放完当前曲目后暂停。通知栏和锁屏控制由 Media3 后台播放服务提供；音频焦点被其他应用接管或设备断开时，应用会提示原因并提供继续操作。

## 6. 发布者如何制作专题

将专题内容放入 `app/src/main/assets/featured_audio/`。兼容旧版的单专题结构是：

```text
featured_audio/
├── pack.json
├── cover.webp
├── 01-track.mp3
└── 01-track.lrc
```

多专题结构是：

```text
featured_audio/
└── topics/
    ├── topic-a/
    │   ├── pack.json
    │   ├── cover.webp
    │   ├── 01-track.mp3
    │   └── 01-track.lrc
    └── topic-b/
        ├── pack.json
        └── 01-track.m4a
```

每一期应在 `pack.json` 中设置稳定的 `id`。专题发布后不要随意更改 ID，否则应用会把它视为新专题，旧完成进度和断点不会自动归入新 ID。`sortOrder` 控制目录排序；`identity`、`edition`、`listeningGuide`、`coverAsset`、`tracks`、`chapters` 和 `notes` 用于构成专题全览。

## 7. 二次打包

如果使用 MT 管理器或其他工具把新的音频、图片、LRC 或 `pack.json` 放入 APK assets，重启应用即可触发重新发现。压缩后的音频会在应用私有缓存中准备播放副本。二次打包必须保持 APK 可安装，并且应使用自己拥有使用与分发权利的媒体资产。

## 8. 常见问题

如果曲目时长暂时显示为未知，通常是 Media3 尚未完成该文件的真实解码确认；开始播放或重新扫描后会更新。若某个文件无法解码，Muse 会提示并继续寻找下一首可用曲目。若搜索不到歌词，请检查 LRC 是否与音频同目录、同名且使用有效时间戳；应用不会联网补齐歌词。
