# APK 内置专题音频架构

Muse 的主业务是随 APK 一起发行的离线专题声音内容；设备本地音乐资料库是辅助能力。v1.9.0 起，应用不再把 APK 内所有音频视为唯一专题，而是支持在一个 APK 内组织多个**独立专题包**，同时保持原有单专题目录的兼容性。

| 层次 | Legacy 单专题 | 多专题目录 |
|---|---|---|
| 资产根目录 | `assets/featured_audio/` | `assets/featured_audio/topics/<topic-id>/` |
| 元数据 | `featured_audio/pack.json` | 每个专题目录各自的 `pack.json` |
| 曲目与节目内容 | 根目录和任意子目录的音频、LRC、封面、章节、笔记 | 当前专题目录内的音频、LRC、封面、章节、笔记 |
| 浏览入口 | 首页本期专题与专题全览 | 首页专题目录横向卡片、专题全览内切换器 |
| 完成与断点 | legacy `default` 专题状态 | 每个稳定专题 ID 的独立私有 DataStore 状态 |
| 播放上下文 | 一条完整专题连续队列 | 切换/播放时为对应专题建立独立完整连续队列 |

## 目录选择规则

当 `featured_audio/topics/` 下没有有效一级专题目录时，应用使用 legacy 根目录作为唯一专题，并为其赋予稳定 ID `default`。当 `topics/` 下存在包含 `pack.json` 或有效音频的一级专题目录时，应用进入目录化模式，只加载这些专题，避免子目录内容被重复归入根专题。

每个多专题包可在 `pack.json` 中配置 `id` 与 `sortOrder`。`id` 仅应使用小写字母、数字、连字符和下划线；缺失时应用由目录名生成。专题按 `sortOrder`、标题和 ID 稳定排序。发布者如要在后续更新中保留同一专题的收听状态，应始终保持该专题的 `id` 不变。

## 数据与播放边界

加载器为每首专题曲目记录所属 `featuredTopicId`。播放器据此在从搜索、书签、节目单或章节直达某曲目时，先切换到该专题的完整曲目队列，再播放或定位。这样可以保证上一首、下一首、循环策略、异常跳过、章节、真实时间轴、完成进度和断点恢复都属于同一专题。

每期专题的完成集合和断点状态以专题 ID 分桶保存于应用私有 DataStore；当前浏览专题的选择也本地保存。legacy 单专题用户在首次写入 `default` 专题的新状态时，会保留已有的完成记录和断点并迁移。全部状态均不联网、不上传，并会随 Android 的运行时包名与共存 APK 隔离。

## 二次打包与容错

扫描仅依赖已安装 APK 的 assets 目录，因此重新签名后的二次打包 APK 仍可添加或替换专题目录内容。音频保持未压缩时，Media3 直接通过 assets 播放；若二次打包工具压缩了音频，加载器会按需复制到版本隔离的私有缓存，随后以文件 URI 播放。单个音频标签异常、损坏或缓存准备失败会被忽略，其他同专题和其他专题内容继续可用。

> 发布者只能在 APK 中放入拥有使用、修改、发行或分发权利的音频、歌词、封面与文案。
