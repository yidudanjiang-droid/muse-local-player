# 专题音频包优先架构

Muse 的首页优先服务于 APK 自带的专题内容，而不是把系统媒体库作为唯一入口。内置音频从 `app/src/main/assets/featured_audio/` 递归扫描，无需设备存储权限；手机本地音乐仍作为辅助资料库提供给用户。

| 内容来源 | 资源位置 | 权限 | 默认入口 | 播放 URI |
|---|---|---|---|---|
| 专题音频包 | `assets/featured_audio/` | 不需要 | 首页“专题音频包” | `asset:///featured_audio/...` |
| 设备本地音乐 | Android `MediaStore` | Android 13+ `READ_MEDIA_AUDIO`；旧版本为存储读取权限 | “设备音乐”页 | `content://media/...` |

专题音频文件按其相对路径或文件名内的数字前缀排列。应用优先通过 `MediaMetadataRetriever` 读取标题、艺人、专辑、时长、年份、曲目号与嵌入封面；无法获取标签时使用稳定的文件名降级规则。内置与设备曲目使用不同的稳定 ID 空间，以避免收藏、队列和播放恢复发生冲突。

首页在存在内置音频时显示专题包的标题、曲目数量、总时长、继续播放入口和最近曲目；在没有内置音频时，显示清晰的构建期资源提示。设备媒体库状态独立呈现，因此用户拒绝设备读取权限不会影响专题音频包播放。
