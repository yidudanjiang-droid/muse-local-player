# 内置专题音频目录

Muse 将 APK 内的音频作为**离线专题内容**播放，不需要读取手机存储权限。v1.9.0 支持两种完全离线的组织方式：继续使用原有的单专题目录，或在同一个 APK 内发布多个可独立切换的专题。

| 方式 | 适用场景 | 入口 |
|---|---|---|
| Legacy 单专题 | 一个 APK 只承载一张专题声音作品。 | `featured_audio/pack.json` 与该目录/子目录中的音频。 |
| 多专题目录 | 一个 APK 承载系列、选集、季刊或多个独立节目。 | `featured_audio/topics/<专题目录>/pack.json` 与其目录内的音频。 |

> **兼容原则：**未创建 `featured_audio/topics/` 时，原有单专题结构、`pack.json`、LRC、章节、封面和旅程状态保持原样。只要 `topics/` 下存在有效专题目录，应用即进入多专题目录模式，以防其内部音频被重复扫描到 legacy 专题。

## Legacy 单专题（继续支持）

将音频直接放入本目录或任意子目录。例如：

```text
app/src/main/assets/featured_audio/
├── pack.json
├── 01-序章.mp3
├── 02-夜曲.m4a
└── bonus/
    └── 03-尾声.flac
```

应用会递归扫描有效音频，并作为首页的一个专题显示。支持 `.mp3`、`.m4a`、`.aac`、`.ogg`、`.wav` 与 `.flac`。标题、艺人、专辑、时长优先从音频标签读取；没有标签时会从文件名生成标题，并使用 `pack.json` 中的默认艺人和专辑。文件名加 `01-`、`02-` 等序号即可控制默认顺序。

## 多专题目录（v1.9.0）

把每一期专题放入 `featured_audio/topics/` 的一个一级子目录。每个专题拥有自己的 `pack.json`、音频、LRC、封面、章节和节目笔记：

```text
app/src/main/assets/featured_audio/
└── topics/
    ├── city-night/
    │   ├── pack.json
    │   ├── cover.webp
    │   ├── 01-opening.mp3
    │   ├── 01-opening.lrc
    │   └── 02-walk-home.m4a
    └── morning-notes/
        ├── pack.json
        ├── 01-first-light.mp3
        └── bonus/
            └── 02-after-rain.flac
```

首页会出现“专题目录”横向卡片，可显示每一期的独立封面、曲目数量和完成状态。专题全览内也能直接切换期数。应用会记住上次浏览的专题；每期的完成记录和断点分别写入应用私有 DataStore，不上传、不联网，也不会互相覆盖。

目录名建议使用小写英文字母、数字、`-`、`_`。若未显式填写 `id`，应用会用目录名生成稳定专题 ID；更改目录名会被视为一个新专题。为保证后续更新中进度不丢失，已发布专题应持续使用相同的 `id`。

## `pack.json` 顶层字段

每个专题目录的 `pack.json` 使用同一份字段契约。所有文本都应为 UTF-8，可选字段缺失时会安全回退。

| 字段 | 说明 |
|---|---|
| `id` | 多专题模式下推荐填写的稳定专题 ID，如 `city-night`。仅用小写字母、数字、`-`、`_`；缺失时回退为目录名。legacy 单专题缺失时使用 `default`，可无缝接续旧版旅程进度。 |
| `sortOrder` | 可选整数，越小越靠前；同序时再按标题和 ID 排序。 |
| `title` | 首页与专题全览主标题。 |
| `eyebrow` | 专题小标识。 |
| `description` | 专题导语。 |
| `defaultArtist` | 音频标签缺失时使用的艺人名称。 |
| `defaultAlbum` | 音频标签缺失时使用的专辑名称。 |
| `playLabel` | 首页播放按钮文字。 |
| `identity` | 系列、策展人或作品身份。 |
| `edition` | 更新批次、年份或修订版说明。 |
| `listeningGuide` | 面向听众的一句离线收听提示。 |
| `coverAsset` | 可选封面路径，支持 `.png`、`.webp`、`.jpg`、`.jpeg`。可写当前专题相对路径 `cover.webp`，或完整 assets 路径。 |
| `tracks` | 按 assets 路径覆盖单曲元数据、章节和笔记的对象。 |

示例：

```json
{
  "id": "city-night",
  "sortOrder": 10,
  "title": "城市夜行",
  "eyebrow": "MUSE · SERIES",
  "description": "一段沿着灯光与街道展开的离线声音漫游。",
  "identity": "深夜电台系列 · Vol. 01",
  "edition": "2026 夏季修订版",
  "defaultArtist": "城市夜行",
  "defaultAlbum": "城市夜行",
  "coverAsset": "cover.webp",
  "listeningGuide": "建议从开场开始，章节之间留一点停顿。",
  "tracks": {
    "01-opening.mp3": {
      "title": "序章",
      "trackNumber": 1,
      "chapters": [
        { "time": "00:00", "title": "开场" },
        { "time": "02:15.500", "title": "主题展开" }
      ],
      "notes": ["本期专题的收听提示。"]
    }
  }
}
```

## 曲目、LRC、章节与节目笔记

`tracks` 的键可以使用完整 assets 相对路径，或使用当前专题目录内的相对路径；反斜杠会被自动标准化。覆盖项优先于音频标签和文件名。相同曲序与标题的曲目进一步按 assets 路径排序，确保二次打包后顺序稳定。

如需离线逐行歌词，将 UTF-8 编码的 `.lrc` 放在音频相同目录且使用相同文件名。例如 `01-opening.mp3` 对应 `01-opening.lrc`。Muse 只读取 APK 内明确提供的 LRC，不联网搜索、下载或生成歌词。每一行可含一个或多个时间标签，支持分、秒、毫秒：

```text
[00:00.00]开场文字
[00:12.450]第一句逐行歌词
[00:24:700][00:36:700]重复出现的同一句
```

`chapters` 支持 `time`（`分:秒`、`分:秒.毫秒`、`分:秒:毫秒`）或 `timestampMs`。专题全览会显示每首曲目的章节数量、首条节目笔记和前 3 个章节的直达入口；播放页还会呈现当前章节、章节时间轴和上一章/重播/下一章快捷操作。

## 多专题播放与旅程边界

每一个专题均有独立的完整连续队列。无论从专题首页、专题全览曲目、章节入口、搜索或书签进入某一期，Muse 都会以该专题的完整曲目顺序建立播放上下文，因而上一首、下一首、完成状态和断点不会串到其他专题。

完成只在 Media3 取得有效真实时长且收听位置达到结尾前约 2 秒时记录。设备音乐、未知时长、单纯点击、章节定位和历史记录都不会伪造成完成。legacy 单专题的既有完成与断点会在首次 v1.9.0 写入时保留并迁移到 `default` 专题，不会因为升级而丢失。

## 已构建 APK 的二次打包

Muse 不会把专题发现逻辑固定在构建时。重新签名并安装/覆盖更新二次打包后的 APK 后，应用会扫描 APK `assets/` 内符合上述目录结构的音频。若二次打包工具压缩了新加入的音频，Media3 无法直接以描述符读取时，应用会将该文件复制到**版本隔离的应用私有缓存**播放；旧版本缓存与未完成的临时文件会被清理。

| 二次打包情形 | 应用行为 |
|---|---|
| 音频保持未压缩 | Media3 直接从 APK assets 播放。 |
| 音频被工具压缩 | 按需复制到应用私有缓存并以本地 URI 播放。 |
| `pack.json` 缺失或字段无效 | 使用稳定的默认标题与元数据，其他有效曲目继续出现。 |
| 单个音频损坏、标签异常或缓存准备失败 | 跳过该文件，继续显示和播放同专题的其余曲目。 |
| 更改已发布专题的 `id` 或目录名 | 该专题会被视为新专题；如需保留进度，请保持 `id` 稳定。 |

> 该目录中的所有内容都会打包进入 APK。仅放入你拥有发行、使用或分发权利的音频、歌词、封面与文案。新增或替换内容后，重新构建 APK 即可。
