# 内置专题音频包

将要随 APK 一起发布的专题音频直接放入此目录或其任意子目录。例如：

```text
app/src/main/assets/featured_audio/
├── 01-序章.mp3
├── 02-夜曲.m4a
└── bonus/
    └── 03-尾声.flac
```

应用会在启动时自动递归扫描此目录，并把识别到的音频作为首页的 **专题音频包** 显示；不需要读取手机存储权限。支持 `.mp3`、`.m4a`、`.aac`、`.ogg`、`.wav` 与 `.flac`。

标题、艺人、专辑、时长和封面会优先读取音频自身的标签；没有标签时，应用会用文件名生成标题，并把艺人和专辑显示为“专题音频包”。文件名前加 `01-`、`02-` 等序号即可控制默认展示顺序。同曲序、同标题的文件会进一步按 assets 路径排序，确保二次打包后的顺序稳定。

如需为当前专题替换默认首页与曲目封面，可先将 `.png`、`.webp`、`.jpg` 或 `.jpeg` 放入 assets（通常置于本目录），再在 `pack.json` 顶层声明 `coverAsset`。路径支持 `featured_audio/cover.webp`、`cover.webp` 或反斜杠写法；无效路径会安全回退默认封面：

```json
{
  "coverAsset": "cover.webp"
}
```

## 专题身份与首听导览（可选）

每个共存专题 APK 都可以在 `pack.json` 顶层声明自己独立的内容身份、版次和首听导览。它们会出现在首页专题主视觉与“本期导览”卡片中；不配置时 Muse 会使用克制的通用导览，不影响原有标题、封面、章节或曲目扫描。

```json
{
  "title": "城市夜行",
  "identity": "深夜电台系列 · Vol. 01",
  "edition": "2026 夏季修订版",
  "listeningGuide": "建议从头播放；在章节间停留片刻，并把想回听的段落保存为书签。"
}
```

字段均为可选 UTF-8 文本。`identity` 适合填写系列、策展人或专题的作品身份；`edition` 适合填写更新批次、年份或限量版说明；`listeningGuide` 建议保持一句简洁的收听指引。不要在这些字段中写入敏感信息或你没有权利使用的品牌内容。

## 离线逐行歌词（可选）

若要在播放页展示逐行同步歌词，只需把 UTF-8 编码的 `.lrc` 文件放在音频**相同目录**，并使用相同文件名。例如 `01-序章.mp3` 对应 `01-序章.lrc`，子目录同样适用。Muse 只读取 APK 内明确提供的 LRC 文件，不联网搜索、下载或生成歌词；没有 LRC 时播放页保持普通界面。

```text
featured_audio/
├── 01-序章.mp3
├── 01-序章.lrc
└── bonus/
    ├── 03-尾声.flac
    └── 03-尾声.lrc
```

每一行可含一个或多个时间标签，支持分、秒、毫秒（`.` 或 `:` 均可用于毫秒分隔）：

```lrc
[00:00.00]开场文字
[00:12.450]第一句逐行歌词
[00:24:700][00:36:700]重复出现的同一句
```

应用会按播放时间高亮当前行，并显示相邻行。无效时间标签或空白文本会自动忽略，不影响音频播放。

## 曲目元数据覆盖（可选）

如需精确控制某些文件，可在同一目录的 `pack.json` 中加入可选 `tracks` 对象。键名可用 `featured_audio/` 完整路径或省略此前缀：

```json
{
  "tracks": {
    "01-序章.mp3": {
      "title": "序章",
      "artist": "专题艺人",
      "album": "专题音频包",
      "trackNumber": 1,
      "year": 2026
    }
  }
}
```

## 章节与节目笔记（可选）

专题音频可以在该文件的 `tracks` 覆盖项中声明章节与节目笔记。播放页会显示当前章节；展开后可点按章节直接跳转到对应时间。`time` 使用 `分:秒`、`分:秒.毫秒` 或 `分:秒:毫秒`，也可直接使用 `timestampMs`；`notes` 是面向听众的简短离线说明。

```json
{
  "tracks": {
    "01-序章.mp3": {
      "chapters": [
        { "time": "00:00", "title": "开场" },
        { "time": "02:15.500", "title": "主题展开" },
        { "timestampMs": 310000, "title": "结语" }
      ],
      "notes": [
        "本期专题的收听提示。",
        "所有章节与笔记均随 APK 离线发布。"
      ]
    }
  }
}
```

无效时间、空标题或空笔记会被自动忽略；不配置章节/笔记时保持普通播放页。覆盖项优先于文件标签和文件名。播放页会以这些已配置的章节时间戳提供“上一章、重播本章、下一章”快捷操作；按钮不推测音频标签时长，只有 Media3 已获得真实时间轴时才会执行精确定位。若二次打包时单个文件损坏、标签异常或无法准备压缩 assets 缓存，应用会跳过该文件，并继续显示其余专题内容。

## 专题播放旅程

首页会单独为本目录及其子目录中的有效专题曲目显示“专题旅程”。完成进度以稳定的 assets 路径关联：播放器必须获得 Media3 的**有效真实时长**，且收听位置达到结尾前约 2 秒内，才会把该曲记为完成。因此，设备音乐、单纯点击、未知时长、章节定位和历史播放记录都不会误增专题完成数。

| 首页状态 | 行为 |
|---|---|
| 尚未完成或进行中 | 显示“已完成 x/y”、进度条和专题顺序中的第一首未完成曲目；点按“开始旅程”或“继续旅程”会从该曲开始播放，并建立完整专题连续队列。 |
| 已全部完成 | 显示本期完成状态；点按“重新开始”会清空本期的完成标记并从第一首播放。 |
| 更换或二次打包专题资源 | 进度按仍存在的稳定 assets 路径匹配；新增曲目自然计为待完成。重新开始仅清除完成标记，不删除 LRC、章节、节目笔记或书签。 |

完成状态只保存在当前应用运行时包名隔离的私有 DataStore，不联网、不上传，也不会与其他共存专题 APK 共享。

> 该目录中的所有内容都会打包进入 APK。仅放入你拥有发行、使用或分发权限的音频、歌词及封面文件。新增或替换内容后，重新构建 APK 即可。
